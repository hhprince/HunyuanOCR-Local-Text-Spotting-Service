# 准确度验收

> 什么时候需要看这篇：**改了任何影响识别结果的参数之后**，或者**把服务换到
> 一台新机器/新后端之后**（比如从开发机换到昇腾生产环境）。

## 1. 为什么不能只看"命中项数"

因为命中项数太粗。

本仓库的公开基准里，三档权重精度在 noisy 样例集上的**行命中率完全相同**
（都是 44/60），字符准确率也只差 0.07 个百分点（96.56% vs 96.49%）。
**看这两个指标，bf16 和 fp16 毫无区别。**

但逐字符比，bf16 和 fp16/fp32 只有 **2/6** 的图片完全相同——4 张图的识别结果
确实不同，差别是单字替换（"考察" vs "考虑"、"权重" vs "权限"）。

所以**必须逐字符比**。

## 2. 两个工具

### 2.1 `tools/compare_runs.py` —— 两次运行互比

不需要标注，只要有两次运行的结果 JSON 就行。

```bash
python tools/compare_runs.py 基线.json 新结果.json
python tools/compare_runs.py a.json b.json c.json --diff
```

输出：

- 两次运行的**字符流完全相同的图片数**（例如 `5/6`）
- 多份结果的两两一致率矩阵
- `--diff` 会打印每张不同的图**第一处不同的位置**和前后各 20 个字符

字符流的定义：把一张图的所有文字块拼起来、**去掉所有空白**，再逐字符比。
去空白是因为模型的切块方式（把一行切成两块还是三块）不该算作识别错误。

### 2.2 `tools/score.py` —— 对着标注打分

有标注时用这个，能给出绝对准确率。

```bash
python tools/score.py 结果.json --truth 标注.json --verbose
```

两个指标：

| 指标 | 定义 | 适合看什么 |
|---|---|---|
| 行命中率 | 每行标准答案，识别结果里有没有原样出现 | 整行对不对 |
| 字符准确率 | 标准答案字符流 与 识别字符流 的最长公共子序列 / 标准答案长度 | 错了几个字、错在哪 |

行命中率适合看"整块有没有读出来"，字符准确率适合看"错得有多细"。

标注文件格式：

```json
{
  "results": [
    {"image": "a.jpg", "lines": ["第一行标准答案", "第二行标准答案"]}
  ]
}
```

## 3. 验收流程

### 3.1 换环境（开发机 → 生产机）

这是最重要的一次验收：**昇腾和 CUDA 的浮点运算舍入不同，结果可能有细微差异。**

```bash
# 1. 生产机上跑同一批回归集
python serve_ocr_prod.py --batch --input-dir /data/regression --output-dir /data/ocr_out

# 2. 和开发机基准逐字符比
python tools/compare_runs.py /data/ocr_out/*.json 开发机基准.json --diff
```

**判定标准：**

| 逐字符一致 | 判定 | 动作 |
|---|---|---|
| 全部一致 | 最好 | 直接放行 |
| 差 1~2 张 | 可接受 | **逐张人工看**：确认是"换了个字"而不是"漏了一块"。漏块是事故，换字是正常差异 |
| 差 ≥ 1/3 | 不可接受 | 停下来查：优先怀疑 dtype、attn 实现、transformers 版本 |
| 大面积不一致 | 出问题了 | 检查生产环境是不是真的用了同一套参数（结果 JSON 的头部字段能看出来） |

### 3.2 改参数

改了 `ocr_core.py` 里任何影响结果的东西（`PROMPT` / `DEFAULT_SCALE` /
`DEFAULT_DTYPE` / `MAX_NEW_TOKENS` / 采样参数），或者换了 transformers 版本：

```bash
# 改之前跑一遍存档，改之后再跑一遍，然后比
python batch_ocr_dev.py --input-dir 回归集 --output-dir output/before
# 改参数
python batch_ocr_dev.py --input-dir 回归集 --output-dir output/after
python tools/compare_runs.py output/before/*.json output/after/*.json --diff
```

**要求：准确度不能下降。** 如果你想证明某个改动是"有意的、且不降准"，就把
新参数和默认参数都比一遍，说明差异落在预期内。

### 3.3 选参数

在候选值之间选（比如放大倍数 1.0 / 1.5 / 2.0），用 `tools/score.py`：

```bash
for s in 1.0 1.5 2.0; do
  python batch_ocr_dev.py --input-dir 回归集 --output-dir output/s$s --scale $s
  printf "scale=%s  " $s
  python tools/score.py output/s$s/*.json --truth 标注.json | tail -2 | tr '\n' ' '
  echo
done
```

**没有通用最优值。** 本仓库的公开基准里 1.0 比 1.5 好，真实翻拍照片上通常相反。

## 4. 建自己的回归集

建议至少 30 张，覆盖你线上会遇到的**难例**：

| 类别 | 要覆盖什么 |
|---|---|
| 典型样本 | 线上最常见的 50% |
| 难例 | 拍糊了、倾斜的、暗的、小字的 |
| 边界例 | 刚好在某个阈值附近的 |
| 已知错例 | 之前踩过坑的那几张 |

**标注写到"文字行"级别**（一行一条），不用标坐标。工具会自动去掉空白再比，
所以你标注时行内怎么断句都行，但**同一张图在两次标注之间要一致**。

## 5. 常见误区

| 误区 | 后果 |
|---|---|
| 用"命中项数"判断改动好坏 | 看不出单字级别的差异，结论会错 |
| 用干净合成图选放大倍数 | 合成图太清晰，测不出真实场景的差异 |
| 只看总准确率不看逐图差异 | 知道"变差了"但不知道为什么变差 |
| 改了参数只跑一次就下结论 | 贪心解码是确定性的，跑一次够；但**换环境**必须比，因为后端舍入不同 |
| 拿不同批图片做前后对比 | 结论无效——图片变了，结果当然不同 |
