# 实验记录

> 本文所有数字都来自**本仓库自带的合成样例**（`tools/make_sample.py` 程序生成，
> 不含任何真实数据），任何人都能复现。复现命令见文末。
>
> 真实业务图片上的绝对准确度取决于具体数据，本文给的是**方法**和**相对关系**，
> 你的数据必须自己测——见 [准确度验收.md](准确度验收.md)。

## 1. 环境

| 项 | 配置 |
|---|---|
| GPU | NVIDIA GeForce RTX 4060 Laptop, 8GB |
| 模型 | tencent/HunyuanOCR（1.12B 参数，`HunYuanVLForConditionalGeneration`） |
| 运行时 | Python 3.12.8 + torch 2.6.0+cu124 + transformers 5.21.0.dev0 |
| 采样 | 贪心（`do_sample=False`，不加 `repetition_penalty`） |
| 注意力 | `sdpa` |

## 2. 三种样例风格

| 风格 | 特征 | 用途 |
|---|---|---|
| `clean` | 正常字号、干净底色 | 跑通流程、黄金基准 |
| `hard` | 11~13px 小字 + 扫描噪点 + 轻微模糊 | 模拟低质量翻拍 |
| `noisy` | hard 再加压对比度 + 强噪点 + 强 JPEG 压缩(q25) | 最接近真实脏图 |

三档的准确率梯度（fp16、scale 1.5）：

| 样例集 | 图数 | 标准答案行数 | 行命中率 | 字符准确率 |
|---|---|---|---|---|
| clean | 6 | 54 | 54/54 (100%) | 100.00% |
| hard | 6 | 60 | 60/60 (100%) | 100.00% |
| noisy | 6 | 60 | 44/60 (73.3%) | 96.49% |

> clean / hard 两档满分的代价是**修了一个解析 bug**，见第 5 节。

## 3. 精度档位对比（noisy 集，scale 1.5）

| dtype | 行命中率 | 字符准确率 | **与 fp16 逐字符相同** |
|---|---|---|---|
| `bfloat16`（官方默认） | 44/60 (73.3%) | 96.56% | **2/6** |
| `float16` | 44/60 (73.3%) | 96.49% | 基准 |
| `float32` | 44/60 (73.3%) | 96.49% | **6/6** |

**这张表是本仓库最想说明的一件事。**

三档的行命中率**完全相同**（44/60），字符准确率也只有 0.07 个百分点的差别
（96.56% vs 96.49%）。**光看这两个指标，bf16 和 fp16 毫无区别。**

但逐字符比，bf16 和 fp16/fp32 只有 **2/6** 的图片字符流完全相同——4 张图的
识别结果确实不同，差别是"长而经/长而结"、"考察/考虑"、"权重/权限"这种
**单字替换**。

**结论：**
- fp16 与 fp32 等价（6/6 逐字符相同），选 fp16；
- bf16 的尾数只有 7 位（fp16 是 10 位），在接近判定边界的图上会做不同的取舍；
- **聚合准确率指标分辨不出"错了一个字"，必须逐字符比**——
  这就是 `tools/compare_runs.py` 存在的理由。

## 4. 放大倍数对比（fp16，noisy 集）

| scale | 进模型的像素 | 行命中率 | 字符准确率 | 与 1.5 逐字符相同 |
|---|---|---|---|---|
| 1.0 | 1166×784（0.91MP） | 46/60 (76.7%) | 97.45% | 0/6 |
| **1.5** | **1736×1176（2.06MP）** | 44/60 (73.3%) | 96.49% | 基准 |
| 2.5 | 2492×1652（4.12MP） | 37/60 (61.7%) | 96.28% | 0/6 |

两点结论：

**1. scale 2.5 一定更差**，而且原因很确定：processor 的
`max_pixels = 2048×2048 = 4.19MP`，2.5x 放大后是 5.71MP，**超限**，
于是 `smart_resize` 把它缩回 2492×1652——等于"先 LANCZOS 放大、再被内部降采样"，
双重重采样把笔画糊掉。

> **显存大不是调大 scale 的通行证**，瓶颈在重采样不在显存。
> 临界点：`scale ≤ 2048×2048 / 原始像素数`，本例约 2.14。

**2. 1.0 和 1.5 谁更好，取决于你的图。**
在本仓库的**合成**样例上 1.0 略好（76.7% vs 73.3%）——因为合成文字本来就清晰，
放大只会引入插值模糊。而在**真实翻拍照片**上情况相反：照片的原始细节比模型
默认的 token 网格更细，放大能把细节带进去，1.5 更好。

**所以默认值的唯一依据只能是实测，不要照抄。** 用
`tools/score.py` 在自己的数据上测 1.0 / 1.5 / 2.0，选最好的那个。
（`ocr_core.DEFAULT_SCALE` 当前是 1.5。）

## 5. 踩到的坑：输出解析让整张图的结果全丢

在跑 clean 样例时发现准确率只有 33%，追下去发现：**6 张图里有 4 张返回 0 个块**。

模型的原始输出里有这种坏格式：

```json
{"box755, 880, 818, 903], "text": "000000"}
```

`'"box": ['` 少了冒号和左方括号。整个数组因此不是合法 JSON，而原来的解析函数
直接返回"解析失败"——**整张图 9 个块全丢，不是丢 1 个**。

修完之后 clean 集从 **18/54 (33.3%) 变成 54/54 (100%)**。

修法（`ocr_core.parse_words`）分两层：

1. 整段按 JSON 解析（正常路径）；
2. 失败则退化成"从原文里逐个抠出 `text` 字段"，**不依赖 JSON 结构**，
   坏的那个元素自动被跳过，其余照常返回。

顺带两个坑：

- **不能用 `rfind("]")` 找数组边界**——box 坐标里本身带方括号
  （`[755, 880, 818, 903]`），`rfind` 会命中坐标里那个 `]`，把数组从中间截断。
- 这种坏输出里**引号数是奇数**（`"box` 那个引号没闭合），所以任何靠
  引号/括号配对来切数组的做法都会错位。**正则抽字段是唯一稳的兜底。**

回归测试见 `tools/test_parser.py`（10 条断言，秒级跑完，不用 GPU）。

## 6. 其它实测结论

### 6.1 提示词：用官方的

官方把 12 种任务的提示词锁死（`TASK_PROMPTS["spotting_json"]`），不让使用者改。
换回官方提示词后，回归集上多找出多个真实文本块（小字字段、零散文字
一类），自造提示词整块漏掉。

### 6.2 采样：贪心，不加 `repetition_penalty`

官方 client 默认带 `repetition_penalty=1.08`，那是给长文档防贪心重复退化用的。
本场景下同一个印刷短语重复出现四五次是**正常内容**，加惩罚实测会掉真块
（编号字段、收件人字段），还会造出重复拼接的假字段名。
**这是刻意偏离官方默认值的**，理由是准确度优先。

### 6.3 eager vs sdpa

`eager` 会物化完整注意力矩阵，显存占用高（放大输入后直接 OOM），
`sdpa` 峰值 2211MiB vs eager 3790MiB，**输出逐字相同**。所以用 sdpa。

### 6.4 机器状态不影响结果

插电 / 电池、GPU 频率高低、进程优先级——**都只影响速度，不影响准确度**。
贪心解码是确定性的，同一份图在什么机器状态下跑，字符流都一样。

### 6.5 速度瓶颈是主机侧，不是显卡

开发机上曾出现"同一张图 99 秒 vs 14 秒"的 6.8 倍差距。排查掉散热、电池、
PCIe 链路、屏幕休眠、线程超订、CPU 饱和、其它进程占 GPU 之后，
**真凶是进程优先级**：后台常驻进程把 Python 进程饿着，CUDA 内核发射被拖慢，
驱动按利用率把 SM 频率从 2600MHz 压到 420MHz。

修法是 `SetPriorityClass(HIGH_PRIORITY_CLASS)`。**教训：看到 GPU 频率低、
利用率低，先看是不是主机侧喂不满，别急着归因给硬件或驱动。**

生产机是独占的多核服务器，一般不会遇到；但如果遇到，先查进程优先级。

## 7. 复现

```bash
# ② 造字纸：造样例（带标注）
python tools/make_sample.py --style noisy --count 6 --out data/samples_noisy

# ③ 试读：跑不同精度
for dt in bfloat16 float16 float32; do
  python batch_ocr_dev.py --input-dir data/samples_noisy --output-dir output/$dt --dtype $dt
done

# ⑤ 校对：打分
python tools/score.py output/float16/*.json --truth data/samples_noisy/ground_truth.json

# ⑤ 校对：逐字符比
python tools/compare_runs.py output/bfloat16/*.json output/float16/*.json --diff
```

⚠️ 逐字符比要求**同一批图片**。改了图片或改了什么参数，结果自然不同——
这正是它要干的事。
